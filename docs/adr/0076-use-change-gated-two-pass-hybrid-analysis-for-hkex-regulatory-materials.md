# Use change-gated two-pass hybrid analysis for HKEX Regulatory Materials

## Decision

Hong Kong Regulatory Materials processing uses deterministic source,
validation, state, rendering, identity, coverage, and release controls around
four narrowly named generative-LLM proposal tasks:

1. `hk-regulatory-update-analysis`;
2. `hk-regulatory-update-challenge`;
3. `hk-regulatory-record-analysis`; and
4. `hk-regulatory-record-challenge`.

The task runner calls none of them merely because a scheduled check occurred.
Complete supported no change stops before generative-model work. A first
baseline, new or changed source unit, changed final update, unresolved
deterministic semantic checkpoint, or invalidated prior proposal may create an
exact task need. Every source unit and update range is accounted as
deterministically resolved, admitted to an exact task, blocked, or quarantined;
there is no silent unanalysed remainder.

The two-pass design is justified because HKEX update, transition, Form, table,
fee, and rule wording can express the same legal relationship in varied ways,
while final source bytes and legal consequences must remain exact. One task
proposes a complete evidence-bound interpretation. A separately contracted
challenge task tests it for omission, overreach, conflict, and unsafe
boundaries. Neither task decides legal status or constructs final serving
bytes.

## Deterministic admission and fast paths

Before any model task, deterministic modules prove:

- exact registered source, observation, artifact, media type, fingerprint,
  language, board, cutoff, contract, and permission admission;
- complete declared inventory and change scope;
- exact English source bytes and any source-explicit hierarchy, locator,
  numbering, table, Form, fee, update, date, or reference facts that can be
  extracted without semantic invention;
- absence of hidden expected answers, case IDs, pair roles, critical tags,
  prompts from source text, secrets, tools, and production capabilities; and
- the task contract, evidence budget, source-unit ledger, prior accepted state,
  and reason the semantic task is necessary.

A deterministic rule resolves the checkpoint directly whenever complete
explicit facts select one exact Source Rulebook branch. A model is not used to
repeat parsing, hashing, date arithmetic, Boolean condition evaluation,
canonical rendering, or another exact operation merely because it is
available.

## Update analysis and challenge

`hk-regulatory-update-analysis` receives only the complete admitted final
update package, exact relevant predecessor and current English products,
affected inventory slice, permitted trigger or approval evidence, prior
accepted branch state, and task contract. It proposes structured:

- update-part and changed-range mapping to exact component and Legal Location
  candidates;
- candidate membership and board evidence when a new or changed object must be
  classified;
- changed words, fixed dates, external conditions, all-of or any-of logic,
  cohorts, transactions, periods, transition ranges, and overlaps;
- predecessor, successor, withdrawal, renumbering, split, merge, and cross-
  reference leads;
- exact supporting source ranges for every proposed fact; and
- established, unresolved, conflicting, and missing facts without guessing.

It may not declare a branch current, infer occurrence from a stated trigger,
reconstruct a current product, select an authority note, issue an identity, or
authorize a record.

`hk-regulatory-update-challenge` receives the same ordinary evidence, the exact
proposal, and a separate challenge contract. It checks the complete update and
affected source-unit ledger for omitted ranges, wrong component or board,
unsupported dates or triggers, missed cohorts or transitions, inconsistent
current-product mapping, false continuity, and hidden uncertainty. It returns
structured objections and evidence only. It does not see protected conformance
truth or replace the first proposal with persuasive free-form prose.

## Record analysis and challenge

`hk-regulatory-record-analysis` receives one admitted accepted-current or
transitional-current English branch, its complete official source-unit tree,
component class, accepted state facts, exact prior record state where relevant,
and task contract. It proposes structured:

- independently usable versus inseparable rule, subrule, list, definition,
  note, appendix, or Practice Note boundaries;
- minimum required governing lead-ins, definitions, scope, qualifications,
  exceptions, provisos, transitions, and attached notes;
- exact cross-reference relationships and unsafe-child findings without
  recursively copying target text;
- table header, row-group, span, unit, note, and value ownership;
- fee category, bracket, amount, currency, basis, timing, activation, and note
  relationships;
- Form Part, instruction, declaration, field-group, control, and signing-
  requirement relationships; and
- every unresolved or ambiguous source boundary with exact support.

It may not rewrite, summarize, translate, correct, complete, or generate source
text; decide final record identity; choose a partition from token positions; or
render final `metadata.text` or `metadata.authority_note`.

`hk-regulatory-record-challenge` receives the same ordinary evidence, proposal,
and a separate challenge contract. It checks every source unit for a detached
qualification, omitted lead-in or note, false independence, unnecessary
overlap, copied target rule, wrong table or fee ownership, discarded Form
obligation, wrong board, uncovered unit, and unacknowledged ambiguity. It
returns evidence-bound objections, not a final record.

## Deterministic validation and Legal Desk decision

After each two-pass task family, deterministic validation proves exact evidence
ranges and hashes, complete ledger accounting, permitted claims, schema and
contract validity, agreement and disagreement structure, absence of invented
source text, and every applicable critical-error rule.

The Hong Kong Regulatory Materials Legal Desk then applies one immutable active
Source Rulebook. It may accept, correct through exact accepted evidence, reject,
block, or quarantine the proposal. It owns membership, board, Fact Authority,
effective state, branch consequence, record boundary, dependency, disposition,
and review routing. Model confidence, agreement, eloquence, or majority does not
create authority.

Ordinary work may be accepted automatically without separate human inspection
only when:

- all required evidence and source-unit accounting are complete;
- analysis and challenge outputs validate and expose no unresolved material
  disagreement;
- one exact stable Source Rulebook path determines every consequence;
- no critical error or human-review rule applies; and
- the exact workflow build is admitted against the frozen catalogue and later
  sealed representative real-source evaluation.

Human review is reserved for missing rulebook coverage, conflicting official
evidence, material unresolved semantics, a genuinely novel source structure,
or another exact review trigger. Ordinary changes do not require human review
merely because a model participated; they are completed and reported.

## Finalization remains deterministic

After the Legal Desk Decision, deterministic modules alone perform:

- date and time-zone arithmetic and all-of or any-of evaluation over accepted
  facts;
- branch-state and component-summary derivation;
- canonical English rendering and controlled authority-note rendering;
- exact table, fee, and Form presentation projection from accepted
  relationships and source bytes;
- token and six-field byte measurement, official-structure partitioning, and
  final part validation;
- source-unit coverage proof, readiness, identity, lineage, traceability,
  release arithmetic, and reports; and
- conformance comparison and attestation construction.

No generative model is in corpus construction, embeddings, promotion,
Pinecone, Azure routing, approval, backup, deployment, or retirement.

## Failure, reuse, and hostile-source behavior

Model transport or schema failure follows the future admitted task profile's
bounded retry rule. The system does not start an open-ended model conversation
or ask another unconstrained model to improvise a repair. An incomplete,
unsupported, conflicting, or failed proposal is blocked or quarantined with its
complete task and source-unit accounting.

Proposal reuse requires exact task-contract, prompt, model, settings, source,
cutoff-relevant state, rulebook, and dependency fingerprints and no
invalidation signal. A changed source range, state fact, rulebook, task
contract, or accepted dependency invalidates affected reuse. Supported no
change creates no new task.

Source text remains inert evidence. Instruction-like legal text cannot change
tools, prompts, contracts, network access, secrets, expected results, approval,
or execution.

## Admission requirements

The 143 frozen synthetic evidence-to-decision cases in ADR 0075 are necessary
but insufficient for model admission. Before any of the four tasks can run, an
immutable task admission package must also bind:

- exact schemas, prompts, evidence views, challenge separation, model,
  settings, token and cost limits, provider-data controls, and deterministic
  pre- and post-validation;
- sealed representative real HKEX updates, consolidated rules, Forms, Fees
  Rules, tables, notes, appendices, Practice Notes, and difficult transitions;
- independently adjudicated protected reference decisions and complete source-
  unit maps;
- per-dimension and critical-error gates, repeated-run policy where the model
  is nondeterministic, and complete-workflow conformance;
- monitoring, sampling, suspension, revocation, regression, and revalidation
  triggers; and
- exact build, rulebook, suite, dependency, task-runner, and admission-profile
  fingerprints.

No model call is authorized by this architecture decision. Exact executable
task contracts and admission values remain future implementation artifacts.

## Consequences and authorization

This ADR settles the high-level Hong Kong Regulatory Materials allocation that
ADRs 0039 and 0043 left open. It does not change the already accepted Hong Kong
Cases or Hong Kong Legislation allocations and does not create a generic model
task for other jurisdictions or material families.

This decision authorizes documentation only. It does not authorize task or
schema implementation, source acquisition, model or embedding-provider calls,
evaluation execution, corpus construction, release publication, Pinecone or
Azure access, promotion, deployment, commit, push, or any remote action.
