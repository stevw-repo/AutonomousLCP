# Post-1-July-1997 Hong Kong Cases Admission Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Account for every official in-scope Judiciary listing from 1 July 1997 onward and produce evidence-bound proposition records with current-authority treatment.

**Architecture:** Convert the Plan 2 Judiciary inventory into immutable judgment bundles, then run the existing two-pass proposition and staged treatment contracts through provider-neutral workflow coordinators. Pure deterministic code owns cutoff, identity, correction, zero-proposition, graph, authority-note, release, and traceability consequences. Plan 6 supplies admitted model execution; this plan keeps all provider calls disabled while proving exact requests and strict outputs.

**Tech Stack:** Python 3.14.7, existing Hong Kong Cases rulebook 0.11.0 lineage, `asklegal_processing` semantic gate, `asklegal_corpus`, immutable evidence vault, Management Register identity ports, Pytest.

**Spec:** `docs/design/HK_V1_LIVE_EXECUTION_SPEC.md`

## Global Constraints

- The inclusive earliest decision date is exactly `1997-07-01`.
- Every official listing receives one acquisition and processing disposition; zero supported propositions is a valid complete outcome.
- Full judgments remain evidence and are never search records.
- Proposition text may be faithful summary or distillation, but authoritative passages and exact locators are always preserved.
- A proposition cannot broaden, omit, or invent the court, opinion path, authority role, qualifications, exceptions, result, or reasoning.
- HKLII cannot prove official completeness.
- Strict model-output parsing and supplied-evidence citation checks remain zero tolerance.
- This plan performs no provider calls; Plan 6 admits and runs the model profile.

## Dependency and exit contract

Depends on Plan 2's complete post-1997 Judiciary inventory and artifacts. Produces:

```python
def build_hk_case_release(
    request: HKCaseReleaseRequest,
    evidence: HKCaseEvidenceReader,
    decisions: HKCaseSemanticDecisionReader,
    identities: HKCaseIssuedIdentities,
) -> HKCaseReleaseResult: ...
```

Plan 6 consumes proposition/treatment request builders, strict output schemas, and the compact authentic golden slice. Plan 7 consumes the complete Cases release and traceability shard only after Plan 6 supplies admitted decisions.
